# Kubernetes upgrade: v1.30 → v1.31

For upgrade prerequisites, version skew policy, etcd backup, drain/cordon order, validation, and generic rollback concepts, see **[Upgrade procedure](./upgrade_procedure.md)**.

This guide focuses on **v1.31** release highlights, API notes, and **command examples** for **`kubeadm` / `kubelet` / `kubectl` at 1.31.14** (Debian/Ubuntu-style packages, **`1.31.14-1.1`**). Adjust package suffixes to match what your repository publishes (`apt-cache madison` / `yum list`). Replace `<control-plane-node>` and `<worker-node>` with your real node names.

---

## Overview

Upgrade **one minor at a time** from **v1.30** to **v1.31**: control plane first (`kubeadm upgrade apply` on the first control plane node, `kubeadm upgrade node` on additional control plane members), then workers one at a time. See the [upgrade procedure](./upgrade_procedure.md) for HA ordering and skew rules.

---

## Prerequisites (v1.31-specific)

- Cluster running Kubernetes **v1.30**
- Read [Kubernetes v1.31 release notes / changelog](https://github.com/kubernetes/kubernetes/blob/master/CHANGELOG/CHANGELOG-1.31.md) and [Kubernetes 1.31: upcoming changes](https://kubernetes.io/blog/2024/07/19/kubernetes-1-31-upcoming-changes/)
- Confirm workloads and controllers are compatible with **v1.31**
- Scan for **deprecated API** usage before upgrading (commands below)
- **etcd 3.5.11+** is required when using kubeadm 1.31 (kubeadm probes etcd via `/livez` and `/readyz`)
- If you use custom kubeadm configuration at **v1beta3**, plan to run `kubeadm config migrate` (kubeadm 1.31 enables **v1beta4** by default)

For etcd backup, staging clusters, and drain flags, use **[Upgrade procedure](./upgrade_procedure.md)**.

## What's new in v1.31

### Major features

1. **kube-proxy nftables mode (beta, on by default)** — alternative dataplane to iptables
2. **Ingress connectivity reliability (stable)** — kube-proxy drains nodes marked for deletion; new `/livez` health endpoint
3. **AppArmor support GA** — cannot disable the `AppArmor` feature gate
4. **PodDisruptionConditions GA** — improved disruption handling
5. **kubeadm v1beta4** — new configuration API; v1beta3 deprecated (supported until 1.34+)

### API changes

#### Graduated to stable (GA)

- `PodDisruptionConditions` — Job and Pod disruption handling improvements
- `AppArmor` — GA support in the API
- `DevicePluginCDIDevices` — Container Device Interface device IDs

#### Deprecations (still served in 1.31; plan ahead)

- **`flowcontrol.apiserver.k8s.io/v1beta3`** for `FlowSchema` and `PriorityLevelConfiguration` — migrate to **`flowcontrol.apiserver.k8s.io/v1`** (available since 1.29). **Removed in v1.32.**
- **Non-CSI scheduler volume limit plugins** (`AzureDiskLimits`, `CinderLimits`, `EBSLimits`, `GCEPDLimits`) — use `NodeVolumeLimits`; removed in v1.32
- **kubeadm `RootlessControlPlane` feature gate** — deprecated in favor of core `UserNamespacesSupport`
- **`volume.beta.kubernetes.io/mount-options`** annotation on PersistentVolumes — warning on create/update

#### Removed APIs and breaking changes

- **In-tree CephFS volume plugin** (`kubernetes.io/cephfs`) — use the [CephFS CSI driver](https://github.com/ceph/ceph-csi/)
- **In-tree Ceph RBD volume plugin** (`kubernetes.io/rbd`) — use the [RBD CSI driver](https://github.com/ceph/ceph-csi/)
- **Legacy in-tree cloud provider integration** — removed from staging; use out-of-tree cloud controllers
- **kubelet flag `--keep-terminated-pod-volumes`** — removed (deprecated since 2017)
- **kube-controller-manager HPA flags** `--horizontal-pod-autoscaler-upscale-delay` and `--horizontal-pod-autoscaler-downscale-delay` — removed (non-functional since 1.12)

### Important notes for this minor

1. **etcd:** kubeadm 1.31 requires **etcd v3.5.11+** (health probes use `/livez` and `/readyz`).
2. **kube-proxy health checks:** `/healthz` on port **10256** now returns **503** when a node carries the `ToBeDeletedByClusterAutoscaler` taint (connection draining). Use **`/livez`** for kube-proxy **liveness** probes instead of `/healthz` to avoid restart loops during node scale-down.
3. **Node status:** With `DisableNodeKubeProxyVersion` (beta, on by default), kubelet may no longer populate `.status.kubeProxyVersion` on Node objects.
4. **kubeadm preflight:** `socat` and `ebtables` are no longer checked during preflight.
5. **Container runtime:** **containerd 1.7.x** or **CRI-O 1.30+** commonly cited; match vendor guidance.

## Pre-upgrade checks

```bash
# 1. Current cluster and client versions (avoid deprecated --short)
kubectl version
kubeadm version

# 2. Version skew — nodes should be v1.30.x before you start
kubectl get nodes -o wide

# 3. Workload health
kubectl get pods -A

# 4. Deprecated API usage (metrics scrape)
kubectl get --raw /metrics | grep apiserver_requested_deprecated_apis

# 5. API Priority and Fairness — migrate v1beta3 before v1.32
kubectl api-resources | grep flowcontrol
kubectl get flowschemas,prioritylevelconfigurations -A

# 6. In-tree Ceph volumes (must migrate to CSI before upgrade)
kubectl get pv -o json | grep -E 'kubernetes.io/cephfs|kubernetes.io/rbd' || true

# 7. etcd backup — follow Upgrade procedure (linked at top)
#    On a control plane node after snapshot:
#    sudo etcdctl snapshot status /path/to/backup/etcd-snapshot.db

# 8. API server readiness (prefer /readyz over deprecated componentstatuses)
kubectl get --raw='/readyz?verbose'
kubectl get --raw='/livez?verbose'

# 9. Control plane and addon health (pod-based)
kubectl get pods -n kube-system
kubectl get events -A --sort-by='.lastTimestamp' | tail -20
```

Confirm your cluster meets the [version skew policy](https://kubernetes.io/releases/version-skew-policy/): kubelet on workers may be at **v1.30** while you upgrade the API server to **v1.31**, but must not be **newer** than the API server.

## Upgrade process

### Step 1: Upgrade control plane (kubeadm)

On the **first** control plane node:

```bash
# 1. Point APT at v1.31 and refresh metadata
curl -fsSL https://pkgs.k8s.io/core:/stable:/v1.31/deb/Release.key \
  | sudo gpg --dearmor -o /etc/apt/keyrings/kubernetes-apt-keyring.gpg

echo 'deb [signed-by=/etc/apt/keyrings/kubernetes-apt-keyring.gpg] \
https://pkgs.k8s.io/core:/stable:/v1.31/deb/ /' \
  | sudo tee /etc/apt/sources.list.d/kubernetes.list

sudo apt-get update
apt-cache madison kubeadm

# 2. Install kubeadm v1.31.14
sudo apt-mark unhold kubeadm
sudo apt-get install -y kubeadm=1.31.14-1.1
sudo apt-mark hold kubeadm

kubeadm version

# 3. Review plan, then apply (after new kubeadm is on disk)
sudo kubeadm upgrade plan
sudo kubeadm upgrade apply v1.31.14

# 4. Drain this control plane node before kubelet/kubectl upgrade
kubectl drain <control-plane-node> --ignore-daemonsets
```

If `kubeadm upgrade apply` fails on preflight or timeouts, `--ignore-preflight-errors=all` is a **last resort** — inspect logs before retrying.

#### Upgrade kubelet and kubectl on the control plane

```bash
sudo apt-mark unhold kubelet kubectl
sudo apt-get install -y kubelet=1.31.14-1.1 kubectl=1.31.14-1.1
sudo apt-mark hold kubelet kubectl

sudo systemctl daemon-reload
sudo systemctl restart kubelet

kubectl uncordon <control-plane-node>
kubectl get nodes
```

#### Additional control plane nodes

On each additional control plane member:

1. Point packages at **v1.31** and install target **kubeadm**
2. Run **`sudo kubeadm upgrade node`** (not `upgrade apply`)
3. **Drain** the node (when upgrading kubelet on that member)
4. Install matching **kubelet** and **kubectl**; restart **kubelet**
5. **Uncordon** and confirm **Ready**

---

### Step 2: Upgrade worker nodes

Upgrade **one worker at a time**.

```bash
# On the worker — install kubeadm and refresh node config
sudo apt-get update   # after v1.31 repo is configured on this host
sudo apt-mark unhold kubeadm
sudo apt-get install -y kubeadm=1.31.14-1.1
sudo apt-mark hold kubeadm

sudo kubeadm upgrade node

# From control plane / admin — drain
kubectl drain <worker-node> --ignore-daemonsets --delete-emptydir-data

# On the worker — kubelet and kubectl
sudo apt-mark unhold kubelet kubectl
sudo apt-get install -y kubelet=1.31.14-1.1 kubectl=1.31.14-1.1
sudo apt-mark hold kubelet kubectl

sudo systemctl daemon-reload
sudo systemctl restart kubelet

kubectl uncordon <worker-node>
kubectl get nodes
```

**RHEL/CentOS:** use `yum install` with `kubeadm-1.31.14-0` (or your repo’s suffix) and `--disableexcludes=kubernetes`, analogous to the control plane section.

Repeat for every worker.

## Post-upgrade verification

```bash
kubectl version
kubeadm version
kubectl get nodes -o wide
kubectl get pods -A
kubectl get pods -n kube-system
kubectl get events -A --sort-by='.lastTimestamp' | tail -20

# API server health
kubectl get --raw='/readyz?verbose'

# Deprecated API usage should trend down after manifest updates
kubectl get --raw /metrics | grep apiserver_requested_deprecated_apis

# Sample workload (clean up when done)
kubectl run nginx-test --image=nginx:latest --port=80
kubectl expose pod nginx-test --port=80 --type=NodePort
kubectl get svc nginx-test
kubectl delete pod nginx-test
kubectl delete svc nginx-test
```

Confirm:

- All nodes report **v1.31.14** (or your chosen patch) and **Ready**
- **kube-system** pods (CNI, CoreDNS, kube-proxy) are running
- If you run kube-proxy DaemonSets with custom probes, verify **liveness** targets **`/livez`** on port **10256** where appropriate

## Rollback

Start with **[Upgrade procedure](./upgrade_procedure.md)** for etcd restore and package downgrade strategy. Rollback is **destructive** and **environment-specific**; rehearse in staging.

Typical steps when reverting to **v1.30**:

1. **Stop kubelet** on affected nodes before restoring etcd or downgrading packages.
2. **Restore etcd** from your pre-upgrade snapshot (paths and topology vary):

   ```bash
   sudo systemctl stop kubelet
   ETCDCTL_API=3 etcdctl snapshot restore /path/to/backup/etcd-snapshot.db \
     --data-dir=/var/lib/etcd-restore
   # Move restored data into place per your etcd/kubeadm layout; restart etcd members safely.
   ```

3. **Downgrade packages** — point repositories at the **v1.30** pkgs.k8s.io repo and install matching **`kubeadm` / `kubelet` / `kubectl`** revisions (`apt-mark unhold` … `apt-get install …=1.30.x` … `apt-mark hold`).
4. On the first control plane node, **`kubeadm upgrade apply v1.30.x --force`** may be required in some failure scenarios — read kubeadm output and logs carefully.

After rollback:

```bash
kubectl get nodes
kubectl get pods -A
kubectl get --raw='/readyz?verbose'
```

## Troubleshooting

### Node stuck in NotReady

```bash
kubectl describe node <node-name>
sudo journalctl -u kubelet -n 100 --no-pager
sudo systemctl restart kubelet
```

### Pods not starting

```bash
kubectl describe pod <pod-name> -n <namespace>
sudo systemctl status containerd
# OR
sudo systemctl status crio
```

### API server not responding

```bash
kubectl get --raw='/readyz?verbose'

ETCDCTL_API=3 etcdctl --endpoints=https://127.0.0.1:2379 \
  --cacert=/etc/kubernetes/pki/etcd/ca.crt \
  --cert=/etc/kubernetes/pki/etcd/server.crt \
  --key=/etc/kubernetes/pki/etcd/server.key \
  endpoint health

sudo crictl pods -n kube-system | grep kube-apiserver
sudo journalctl -u kubelet -n 100 --no-pager
```

### kubeadm upgrade preflight failures

- **etcd too old:** upgrade etcd to **3.5.11+** before kubeadm 1.31.
- **Deprecated APIs in use:** address metrics from `apiserver_requested_deprecated_apis` and migrate manifests (especially APF **v1beta3** and Ceph in-tree volumes).

## Summary

- Back up etcd and read the **v1.31** changelog before changing binaries.
- Migrate **Ceph in-tree volumes** to CSI and **APF v1beta3** manifests to **v1** before or during this upgrade window.
- **Control plane first** (`kubeadm upgrade plan` → `kubeadm upgrade apply`, then `upgrade node` on other masters).
- **Workers** one by one with **drain** / **uncordon**.
- Validate with **`kubectl version`**, **`/readyz`**, **nodes**, **kube-system**, and deprecated API metrics — not `kubectl get componentstatuses` or `kubectl version --short`.

**Rough downtime:** on the order of minutes per control plane member (HA reduces user-visible impact) and per worker, depending on workload eviction and image pulls.
